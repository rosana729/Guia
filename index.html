01¿Qué es un algoritmo?

Un algoritmo es una secuencia finita y ordenada de pasos precisos que permite resolver un problema o realizar una tarea. Usamos algoritmos todo el tiempo sin darnos cuenta: una receta de cocina, las instrucciones para armar un mueble o el camino para llegar a la escuela.

Características de un buen algoritmo

CaracterísticaSignificado
PrecisoCada paso está claramente definido, sin ambigüedades.
OrdenadoLos pasos siguen una secuencia lógica.
FinitoTiene un inicio y un fin; termina en algún momento.
DefinidoCon los mismos datos de entrada, siempre da el mismo resultado.
GeneralSirve para cualquier conjunto de datos válido, no para un solo caso.

Formas de representar un algoritmo

Diagrama de flujoRepresentación gráfica mediante símbolos estandarizados unidos por flechas. Ideal para visualizar el recorrido de la lógica.
PseudocódigoRepresentación escrita en lenguaje natural estructurado, a mitad de camino entre el español y un lenguaje de programación.
Actividad de aperturaPedir a los estudiantes que escriban los pasos para "preparar un mate" o "cruzar la calle". Luego intercambiar y que otro compañero los siga al pie de la letra. Aparecen rápido los pasos ambiguos u omitidos: es la mejor forma de mostrar por qué un algoritmo necesita precisión.

02Etapas para resolver un problema

Antes de dibujar o escribir, conviene analizar el problema. Un esquema útil es Entrada → Proceso → Salida:

EtapaPregunta guíaEjemplo: área de un rectángulo
1. Análisis¿Qué me piden? ¿Qué datos tengo?Calcular el área conociendo base y altura.
2. Entrada¿Qué datos necesito pedir?base, altura
3. Proceso¿Qué cálculos o decisiones hago?area ← base * altura
4. Salida¿Qué resultado muestro?area
5. DiseñoRepresentar con diagrama y/o pseudocódigo.Ver secciones siguientes.
6. Prueba¿Funciona con distintos datos?base=4, altura=3 → 12 ✔

03Variables, tipos de datos y operadores

Una variable es un espacio de memoria con un nombre, donde se guarda un valor que puede cambiar durante la ejecución. Una constante es un valor que no cambia (por ejemplo, PI = 3.1416).

Reglas para nombrar variables

  • Empezar con una letra; pueden contener letras, números y guion bajo.
  • Sin espacios, tildes ni símbolos: nota_final ✔ · nota final ✘ · 1nota ✘
  • Usar nombres descriptivos: precio es mejor que x.
  • No usar palabras reservadas (Si, Mientras, Leer…).

04Diagrama de flujo: símbolos y reglas

Los diagramas de flujo usan símbolos estandarizados (norma ANSI/ISO 5807). Estos son los más usados en la enseñanza:

SímboloNombreUso
TerminalIndica el inicio y el fin del algoritmo.
Entrada / SalidaLectura de datos o muestra de resultados.
ProcesoCálculos y asignaciones.
DecisiónEvalúa una condición; tiene dos salidas (Sí / No).
DocumentoSalida impresa (variante de salida).
SubprocesoLlama a un procedimiento definido aparte.
ConectorUne partes del diagrama que están lejos o en otra página.
Línea de flujoIndica el sentido en que se recorre el algoritmo.

Reglas para construir un diagrama de flujo

  1. Todo diagrama tiene un solo Inicio y un solo Fin.
  2. Se lee de arriba hacia abajo y de izquierda a derecha.
  3. Las líneas de flujo deben ser rectas (horizontales o verticales) y no cruzarse; si es necesario, usar conectores.
  4. Ninguna línea debe quedar "suelta": todas conectan dos símbolos.
  5. Cada símbolo de proceso o entrada/salida tiene una entrada y una salida.
  6. El rombo de decisión tiene una entrada y dos salidas, etiquetadas Sí/No (o V/F).
  7. El texto dentro de cada símbolo debe ser breve y claro.

05Pseudocódigo: sintaxis básica

El pseudocódigo no tiene una sintaxis única, pero es muy común usar la convención de PSeInt, una herramienta gratuita muy difundida en escuelas de Latinoamérica que además permite ejecutar el pseudocódigo y generar su diagrama de flujo automáticamente.

Estructura general

Algoritmo NombreDelAlgoritmo
    Definir variable Como Entero   // declaración
    Escribir "Mensaje"              // salida
    Leer variable                    // entrada
    variable <- variable + 1          // asignación / proceso
FinAlgoritmo

Definir … Como …Declarar variables y su tipo— (opcional)
LeerIngresar datosEntrada
EscribirMostrar datos o mensajesSalida
<-Asignar un valorProceso

Segun … Hacer … FinSegunDecisión múltipleDecisión múltiple

Buenas prácticasUsar sangría (indentación) dentro de cada bloque, escribir comentarios con //, una instrucción por línea, y mostrar mensajes antes de cada Leer para que el usuario sepa qué ingresar.

06Estructura secuencial

Las instrucciones se ejecutan una después de otra, en orden, sin saltos ni repeticiones. Es la estructura más simple.

Ejemplo 1 · Sumar dos números

Enunciado: pedir dos números al usuario y mostrar su suma.

Algoritmo SumarDosNumeros
    Definir a, b, suma Como Real
    Escribir "Ingrese el primer número:"
    Leer a
    Escribir "Ingrese el segundo número:"
    Leer b
    suma <- a + b
    Escribir "La suma es: ", suma
FinAlgoritmo

Observar cómo cada símbolo del diagrama corresponde a una o más líneas del pseudocódigo.

Ejemplo 2 · Promedio de tres notas

Algoritmo PromedioTresNotas
    Definir n1, n2, n3, prom Como Real
    Escribir "Ingrese las tres notas:"
    Leer n1, n2, n3
    prom <- (n1 + n2 + n3) / 3     // ¡los paréntesis son clave!
    Escribir "Promedio: ", prom
FinAlgoritmo

07Estructuras condicionales (de decisión)

Permiten que el algoritmo tome caminos distintos según se cumpla o no una condición.

7.1 Condicional simple Si … Entonces

Si la condición es verdadera, ejecuta un bloque; si es falsa, no hace nada y continúa.

Si nota >= 6 Entonces
    Escribir "Aprobado"
FinSi

7.2 Condicional doble Si … Entonces … SiNo

Ejemplo 3: determinar si un número es par o impar.

Algoritmo ParOImpar
    Definir n Como Entero
    Escribir "Ingrese un número:"
    Leer n
    Si n MOD 2 = 0 Entonces
        Escribir "Par"
    SiNo
        Escribir "Impar"
    FinSi
FinAlgoritmo
Clave didácticaUn número es par si el resto de dividirlo por 2 es cero. El operador MOD suele ser nuevo para los estudiantes: vale la pena practicarlo antes (7 MOD 3 = 1, 10 MOD 5 = 0).

7.3 Condicionales anidados

Un Si dentro de otro. Ejemplo 4: clasificar una nota.

Algoritmo ClasificarNota
    Definir nota Como Real
    Leer nota
    Si nota >= 7 Entonces
        Escribir "Promocionado"
    SiNo
        Si nota >= 4 Entonces
            Escribir "Regular"
        SiNo
            Escribir "Desaprobado"
        FinSi
    FinSi
FinAlgoritmo

7.4 Condiciones compuestas Y · O · NO

Si edad >= 18 Y tieneDNI = "S" Entonces
    Escribir "Puede votar"
FinSi

7.5 Decisión múltiple Segun

Útil cuando una variable puede tomar varios valores concretos. Ejemplo 5: día de la semana.

Segun dia Hacer
    1: Escribir "Lunes"
    2: Escribir "Martes"
    3: Escribir "Miércoles"
    4: Escribir "Jueves"
    5: Escribir "Viernes"
    6, 7: Escribir "Fin de semana"
    De Otro Modo:
        Escribir "Día inválido"
FinSegun

08Estructuras repetitivas (ciclos o bucles)

Permiten repetir un bloque de instrucciones varias veces. Antes de verlas, conviene introducir dos tipos de variables muy usadas:

ContadorAumenta en una cantidad fija: cont <- cont + 1. Sirve para contar cuántas veces ocurre algo. Se inicializa en 0.
AcumuladorSuma valores variables: total <- total + precio. Sirve para sumar. Se inicializa en 0 (o en 1 si acumula productos).

8.1 Ciclo Para cantidad conocida

Se usa cuando sabemos de antemano cuántas veces se repite. Ejemplo 6: tabla de multiplicar.

Algoritmo TablaMultiplicar
    Definir n, i Como Entero
    Escribir "¿Qué tabla?"
    Leer n
    Para i <- 1 Hasta 10 Con Paso 1 Hacer
        Escribir n, " x ", i, " = ", n * i
    FinPara
FinAlgoritmo

El ciclo Para hace automáticamente tres cosas: inicializa i, verifica la condición y la incrementa. En el diagrama esas tres acciones se ven por separado.

8.2 Ciclo Mientras pregunta antes

Repite mientras la condición sea verdadera. Como evalúa al principio, puede no ejecutarse nunca. Ejemplo 7: sumar números hasta que se ingrese 0.

Algoritmo SumarHastaCero
    Definir num, total, cant Como Real
    total <- 0                          // acumulador
    cant <- 0                           // contador
    Escribir "Ingrese un número (0 para terminar):"
    Leer num
    Mientras num <> 0 Hacer
        total <- total + num
        cant <- cant + 1
        Leer num                        // ¡sin esto, ciclo infinito!
    FinMientras
    Escribir "Total: ", total, " en ", cant, " números"
FinAlgoritmo

8.3 Ciclo Repetir pregunta después

Ejecuta el bloque y luego evalúa; se repite hasta que la condición sea verdadera. Siempre se ejecuta al menos una vez. Ideal para validar datos. Ejemplo 8:

Repetir
    Escribir "Ingrese una nota entre 1 y 10:"
    Leer nota
Hasta Que nota >= 1 Y nota <= 10

¿Cuál ciclo elijo?

Ciclo¿Cuándo usarlo?Mínimo de ejecucionesCondición
ParaSé cuántas veces se repite0Controlada por contador
MientrasNo sé cuántas veces; quizás ninguna0Se repite mientras sea Verdadera
RepetirNo sé cuántas veces; al menos una1Se repite hasta que sea Verdadera

09Prueba de escritorio

La prueba de escritorio consiste en ejecutar el algoritmo "a mano", anotando en una tabla el valor de cada variable paso a paso. Es la herramienta más importante para detectar errores de lógica y para que los estudiantes entiendan qué hace el algoritmo.

Prueba del Ejemplo 7 con las entradas: 5, 3, 8, 0

Pasonumnum <> 0 ?totalcantSalida
Inicio——00
Leer5V51
Leer3V82
Leer8V163
Leer0F163Total: 16 en 3 números
ConsejoProbar siempre con casos "normales", casos límite (0, números negativos, el valor exacto del corte como nota = 6) y casos inválidos.

11Ejercicios con soluciones

Para cada ejercicio: identificar entrada, proceso y salida; hacer el diagrama de flujo; escribir el pseudocódigo; realizar una prueba de escritorio.

Nivel 1 · Secuenciales

  1. Calcular el área y el perímetro de un rectángulo.
    Ver solución 
    Algoritmo Rectangulo
    Definir base, altura, area, perim Como Real
    Leer base, altura
    area <- base * altura
    perim <- 2 * (base + altura)
    Escribir "Área: ", area, " Perímetro: ", perim
FinAlgoritmo
  2. Convertir una temperatura de grados Celsius a Fahrenheit (F = C × 9/5 + 32).
    Ver solución 
    Algoritmo CelsiusAFahrenheit
    Definir c, f Como Real
    Leer c
    f <- c * 9 / 5 + 32
    Escribir c, " °C = ", f, " °F"
FinAlgoritmo
  3. Calcular el precio final de un producto aplicando un 21% de IVA.
    Ver solución 
    Algoritmo PrecioConIVA
    Definir precio, final Como Real
    Leer precio
    final <- precio * 1.21
    Escribir "Precio final: $", final
FinAlgoritmo

Nivel 2 · Condicionales

  1. Leer dos números y mostrar cuál es el mayor (o si son iguales).
    Ver solución 
    Algoritmo Mayor
    Definir a, b Como Real
    Leer a, b
    Si a > b Entonces
        Escribir "El mayor es ", a
    SiNo
        Si b > a Entonces
            Escribir "El mayor es ", b
        SiNo
            Escribir "Son iguales"
        FinSi
    FinSi
FinAlgoritmo
  2. Un comercio hace 10% de descuento si la compra supera $50.000. Mostrar el total a pagar.
    Ver solución 
    Algoritmo Descuento
    Definir compra, total Como Real
    Leer compra
    Si compra > 50000 Entonces
        total <- compra * 0.9
    SiNo
        total <- compra
    FinSi
    Escribir "Total a pagar: $", total
FinAlgoritmo
  3. Leer tres lados y decir si el triángulo es equilátero, isósceles o escaleno.
    Ver solución 
    Algoritmo TipoTriangulo
    Definir a, b, c Como Real
    Leer a, b, c
    Si a = b Y b = c Entonces
        Escribir "Equilátero"
    SiNo
        Si a = b O b = c O a = c Entonces
            Escribir "Isósceles"
        SiNo
            Escribir "Escaleno"
        FinSi
    FinSi
FinAlgoritmo

Nivel 3 · Repetitivas

  1. Mostrar los números del 1 al 100 y luego la suma de todos ellos.
    Ver solución 
    Algoritmo UnoAlCien
    Definir i, suma Como Entero
    suma <- 0
    Para i <- 1 Hasta 100 Hacer
        Escribir i
        suma <- suma + i
    FinPara
    Escribir "Suma: ", suma      // resultado: 5050
FinAlgoritmo
  2. Leer las notas de N alumnos y mostrar el promedio del curso y cuántos aprobaron (nota ≥ 6).
    Ver solución 
    Algoritmo NotasCurso
    Definir n, i, aprob Como Entero
    Definir nota, suma Como Real
    Escribir "Cantidad de alumnos:"
    Leer n
    suma <- 0
    aprob <- 0
    Para i <- 1 Hasta n Hacer
        Escribir "Nota del alumno ", i, ":"
        Leer nota
        suma <- suma + nota
        Si nota >= 6 Entonces
            aprob <- aprob + 1
        FinSi
    FinPara
    Escribir "Promedio: ", suma / n
    Escribir "Aprobados: ", aprob
FinAlgoritmo
  3. Pedir una contraseña hasta que el usuario escriba "1234" y contar los intentos.
    Ver solución 
    Algoritmo Contrasena
    Definir clave Como Cadena
    Definir intentos Como Entero
    intentos <- 0
    Repetir
        Escribir "Ingrese la contraseña:"
        Leer clave
        intentos <- intentos + 1
    Hasta Que clave = "1234"
    Escribir "Acceso concedido en ", intentos, " intentos"
FinAlgoritmo
  4. Calcular el factorial de un número (5! = 5 × 4 × 3 × 2 × 1 = 120).
    Ver solución 
    Algoritmo Factorial
    Definir n, i, fact Como Entero
    Leer n
    fact <- 1                       // acumulador de producto: empieza en 1
    Para i <- 1 Hasta n Hacer
        fact <- fact * i
    FinPara
    Escribir n, "! = ", fact
FinAlgoritmo

Desafíos integradores sin solución

  1. Juego de adivinanza: la computadora "piensa" un número del 1 al 100 y el usuario intenta adivinarlo; en cada intento se indica "mayor" o "menor".
  2. Cajero automático: menú con opciones (consultar saldo, depositar, extraer, salir) usando Segun dentro de un ciclo.
  3. Leer números hasta ingresar un negativo y mostrar el mayor, el menor y el promedio.

ClaseTemaActividad sugerida

12EvaluaciónProblema nuevo: análisis, diagrama, pseudocódigo y prueba de escritorio.

Criterios de evaluación sugeridos

  • Análisis: identifica correctamente entradas, procesos y salidas.
  • Simbología: usa cada símbolo del diagrama de forma adecuada.
  • Lógica: el algoritmo resuelve el problema para todos los casos, incluidos los límite.
  • Sintaxis: el pseudocódigo respeta la estructura, cierra bloques y usa sangría.
  • Verificación: realiza la prueba de escritorio y corrige errores encontrados.
Herramientas recomendadasPSeInt (gratuito: escribe pseudocódigo, lo ejecuta y genera el diagrama de flujo), DFD (diseño y ejecución de diagramas de flujo), draw.io / diagrams.net (dibujo de diagramas) y Scratch como paso previo para los más chicos.
